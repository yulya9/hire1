# Спецификация: Hire, вакансия за четыре ответа

Версия 2 от 10 ноября 2026. Это источник правды: если код расходится с этим файлом, неправ код. Новое поведение сначала записывается здесь, потом в `прототип/index.html`.

## 1. Зачем это

Заказчик (нанимающий менеджер) не умеет и не любит писать описание вакансии. Он отвечает на четыре вопроса вслух или текстом. Из ответов система сама собирает текст вакансии с разделами. Сложность сборки спрятана: человек видит вопрос, поле, круг и в конце готовый документ.

Это вакансия, а не резюме кандидата. Спрашиваем про того, кого ищут.

**Задача пользователя.** Когда мне нужно открыть вакансию, а писать описание некогда, я хочу ответить на несколько вопросов голосом и получить текст, который можно скопировать и опубликовать.

**Три уровня готовности из задания.**

| Уровень | Что это | Статус |
|---|---|---|
| Минимум | Голос заполняет форму | сделано |
| Средний | Проверка, что ответ по смыслу полный | сделано, локальные правила (раздел 7) |
| Максимум | Структурированный текст вакансии | сделано: шаблон без ключа, Claude с ключом (раздел 9) |

## 2. Объём

| Входит | Не входит | Отложено |
|---|---|---|
| Старт, 4 вопроса по одному, текст и голос в одном поле | Название должности (должность не выдумываем) | Серверное распознавание (Whisper) для браузеров без `SpeechRecognition` |
| Проверка ответа: пустой, слишком короткий, слова-паразиты | Условия работы, зарплата, график | Аналитика событий |
| Круг: 4 четверти по 15 засечек, реакция на голос | Сохранение после закрытия вкладки и в новой вкладке | Автотесты экрана (Playwright) |
| Продолжение после обновления этой вкладки (принятые ответы) | Недописанный текст текущего поля | |
| Сборка документа вакансии (шаблон или Claude) | Вход, аккаунты, список вакансий, публикация | Скачивание файла, отправка в ATS |
| Правка разделов, копирование, «Добавить», «Назад» | Мобильное приложение | |
| Тёмная и светлая тема, адаптив от 320 px | | |

Приоритеты (MoSCoW): Must: 4 вопроса, голос и текст, проверка, документ, копирование. Should: «Назад», «Добавить», правка раздела, Claude. Could: анимация старта. Won't: всё из колонки «Не входит».

## 3. Вопросы

В задании вопросы звучат от третьего лица («он выполняет», «он работает эти 6 месяцев»). На экране «сотрудник будет выполнять», «сотрудник работает последние 6 месяцев»: в интервью голое «он» без подписи непонятно. Смысл и порядок те же. Это осознанное отличие от задания, решение автора.

| № | Вопрос | Раздел в документе | Тип | Пример для подсказки |
|---|---|---|---|---|
| 1 | Какие две-три задачи сотрудник будет выполнять каждый день? | Чем предстоит заниматься | список | «пишу код на Python, провожу код-ревью, разбираю баги» |
| 2 | Над каким проектом сотрудник работает последние 6 месяцев? | Проект, над которым идёт работа | фраза | «разрабатывал мобильное приложение для банка» |
| 3 | В ближайшие полгода сотрудник продолжит работать над этим проектом или возьмётся за другой? За какой именно? | Ближайшие полгода | фраза | «продолжит развивать приложение и возьмёт новый модуль платежей» |
| 4 | Какими особыми инструментами, программами и знаниями должен владеть сотрудник, чтобы эффективно выполнять свою работу? | Инструменты и знания | список | «Python, SQL, Git, английский не ниже B1» |

## 4. Поток

```
Старт ──«Начать»──► Вопрос 1 ─► Вопрос 2 ─► Вопрос 3 ─► Вопрос 4 ──► Сборка ──► Результат
                       ▲   «Назад» на 2–4 возвращает на предыдущий     │             │
                       └───────────────────────────────────────────────┘      «Добавить»
                                                                          ведёт к пробелу
Сборка ──сбой──► Ошибка ──«Повторить»──► Сборка
                         └─«Изменить ответы»──► Вопрос 4 (дальше «Назад»)
```

Если страницу обновили посреди интервью, на старте появляются «Продолжить» и «Начать заново» (раздел 5). После сборки и после «Начать заново» сохранённое стирается. «Изменить ответы» на экране сбоя открывает четвёртый вопрос текстом, без автоматической записи.

Фаза экрана (`S.phase`): `idle`, `listening`, `review`, `building`, `failed`, `result`. Фазы `listening` и `review` — это один и тот же экран вопроса: в первой идёт запись, во второй нет. Подробная матрица состояний в `STATES.md`.

## 5. Старт и экран вопроса

**Старт:** заголовок, подпись и кнопка «Начать». Если в этой вкладке есть незаконченное интервью, вместо «Начать» главная кнопка «Продолжить» (открывает вопрос, на котором остановились, с принятыми ответами и недописанным текстом) и под ней тихая ссылка «Начать заново» (стирает ответы и сразу открывает первый вопрос; так же ведёт себя «Начать заново» на экране результата). На таком старте круг уже показывает закрашенные четверти за принятые ответы, а подпись вместо приглашения говорит: «Вы остановились на вопросе N из 4. Ответы сохранены.» Принятые ответы, номер вопроса и недописанный текст в поле лежат в `sessionStorage` этой вкладки и стираются при сборке и при любом «Начать заново». Новая вкладка и закрытие этой начинают с пустого старта.

**Вопрос.**

Сверху вниз: круг (канва из 60 засечек и точечный шар в центре), таймер (только во время записи), вопрос, поле ответа с кнопкой микрофона внутри, две кнопки «Пропустить» и «Дальше» (на четвёртом «Создать вакансию»). В углах карточки: слева стрелка «Назад» (только на вопросах 2–4), справа крестик.

- Подписи «Вопрос N из 4» на экране нет: прогресс показывает круг. Номер вопроса читают только скринридеры (`aria-label` у заголовка).
- Поле одно и для голоса, и для текста. При начале записи курсор в поле, диктовка пишет прямо в него. Если человек печатает во время записи, запись останавливается, текст остаётся.
- Микрофон в поле: включает и выключает запись.
- «Пропустить» оставляет вопрос без ответа и идёт дальше. «Дальше» отправляет ответ.
- Крестик: если ответы уже есть, первый клик не стирает, а подсвечивает крестик янтарным на 3 секунды; второй клик в это время начинает заново.
- Все реплики системы (подсказка дозапроса, ошибка голоса) живут в одном месте, в строке под полем: новая заменяет прежнюю, поле при этом не сдвигается. Подсказка жёлтая, ошибка красная. Подсказка остаётся до нажатия «Дальше». Любое нажатие «Дальше» убирает ошибку голоса.

## 6. Круг

60 засечек, 4 четверти по 15. Четверть загорается оранжевым, когда ответ на её вопрос принят полностью. Принятый «короткий» ответ четверть не закрашивает.

| Состояние | Что видно |
|---|---|
| Старт | Круг 320 px. Засечки упруго тянутся к курсору мыши; без мыши невидимый курсор медленно бродит вокруг. Центр пуст |
| Вопрос, идёт запись | Круг 280 px. Шар в центре пульсирует, засечки текущей четверти вытягиваются от голоса. Бегущая искра по четверти, когда тихо |
| Какой это вопрос | Текущая четверть всегда видна: её 15 засечек чуть длиннее остальных, пока в ней нет голоса (в светлой теме ещё и темнее, в тёмной цвет круга не меняется). Закрашенные оранжевые четверти позади, тусклые впереди. Номер текущей четверти равен номеру вопроса, даже если предыдущие пропущены |
| Вопрос, запись остановлена | Круг и шар неподвижны. Если человек печатает или диктует системой, шар и засечки откликаются и гаснут через две секунды после последнего ввода |
| Ошибка голоса | Текущая четверть янтарная, если речи не слышно, нет сети распознавания или запись не запустилась. Красная, если нет доступа к микрофону, микрофон не найден, распознавание недоступно или это уже третья ошибка подряд. Остальное как было |
| Сборка | Шар вращается, засечки загораются по кругу |
| Результат | Круга на экране результата нет: статус показывает метка в шапке документа («Готова» с зелёной точкой или «Черновик» с жёлтой) |
| Результат-черновик | Закрашены четверти с полными ответами, в центре пусто |
| Сбой | Засечки красные |

При `prefers-reduced-motion`: шар не рисуется, четверть загорается сразу без бегущей искры, магнитного эффекта на старте нет.

**Переход между вопросами.** При смене вопроса заголовок и поле ответа съезжают на 32 px в сторону движения (вперёд справа, «Назад» слева) и проявляются за 0,36 с; поле начинается на 0,04 с позже. Круг в это время дозаполняет предыдущую четверть. При `prefers-reduced-motion` без сдвига.

## 7. Правила ответа

1. **Пустой ответ не принимается никогда.** Пустое поле, пробелы и только слова-паразиты (ну, вот, короче, ааа) показывают подсказку «Ответ пустой. Скажите или напишите хотя бы пару слов или пропустите вопрос» при каждом нажатии «Дальше». Выйти можно только «Пропустить». Подсказка «Ответ пустой…» пропадает, как только в поле появился текст.
2. **Достаточный ответ** (после чистки от слов-паразитов): для вопроса 1 (список задач) не меньше двух пунктов или пяти слов; для вопроса 4 (инструменты) не меньше двух пунктов или двух слов, потому что «фигма Photoshop» это два названия подряд; для остальных не меньше трёх слов.
3. **Недостаточный ответ.** Первый раз остаёмся на вопросе и показываем «Можно подробнее? Например: » и пример из таблицы раздела 3. Если человек нажал «Дальше» ещё раз, ответ принимается, но помечается «коротко».
4. **Готовность.** Метка «Готова» только если на все четыре вопроса есть ответ и ни один не «коротко». Иначе метка в шапке документа «Черновик», а у короткого раздела рядом с названием слово «коротко». Раздел, очищенный правкой, снова считается пробелом. После правки раздела готовность считается так же, как у ответа на вопрос: если текст по-прежнему короткий, пометка «коротко» остаётся.
5. **Нельзя пропустить всё.** «Пропустить» есть на каждом вопросе, в том числе на первом. Если ни на один вопрос ответа нет, то на последнем вопросе пропуск не срабатывает: человек остаётся на нём, под полем появляется подсказка «Ответьте хотя бы на один вопрос, иначе вакансию не собрать», введённый текст сохраняется. Круга и возврата на первый вопрос нет.
6. **«Назад».** Текст в поле сохраняется как есть (недописанный тоже, но четверть остаётся пустой), предыдущий ответ возвращается в поле. «Дальше» идёт по порядку.
7. **Пробелы** на черновике закрываются кнопкой «Добавить» у пустого раздела (открывает именно этот вопрос) или правкой раздела по клику. Отдельной кнопки «Дополнить» нет.
8. Первое нажатие «Дальше» на коротком ответе после «Назад» снова показывает подсказку один раз.

## 8. Голос

Технология: Web Speech API (`SpeechRecognition`), язык `ru-RU`, непрерывный режим, промежуточные результаты. Работает в Chrome и Edge по `https` или `localhost`. В Firefox голоса нет: микрофона на экране нет, поле работает как обычное текстовое, ошибки не показываются, весь сценарий проходится текстом. В Safari распознавание речи частичное и не проверялось: страница пробует его включить, а если не получилось, показывает ту же ошибку, что и при любом сбое голоса, и поле остаётся текстовым.

| Правило | Значение |
|---|---|
| Запуск | Сам при открытии вопроса (если браузер поддерживает и режим не текстовый) |
| Тишина после последней фразы | 25 секунд, затем запись останавливается, текст остаётся |
| Не услышали речь | 10 секунд от старта, ошибка «Не слышно речи» |
| Chrome сам закончил распознавание | Перезапускаем. Если оборвалось быстрее 1,5 с шесть раз подряд, останавливаемся |
| Скрыли вкладку | Останавливаем через 30 секунд, не раньше |
| Escape, кнопка микрофона | Остановка без сообщений об ошибке |
| Печать во время записи | Запись останавливается, текст остаётся |
| Хвост прошлого ответа | Первые 3 секунды новой записи отбрасываем фразу, дословно входящую в только что отправленный ответ |
| Таймер | `00:00`, виден только во время записи |
| Жёсткая ошибка или три ошибки подряд | Интервью переходит в текстовый режим: следующие вопросы сами запись не включают. Кнопка микрофона в поле остаётся, ею запись можно включить снова. Жёсткие ошибки: нет доступа, микрофон не найден, распознавание недоступно |

Звук с микрофона нужен только для анимации (`AnalyserNode`), запись нигде не сохраняется и не отправляется.

## 9. Сборка вакансии

Два пути, выбор зависит от того, введён ли ключ API (раздел ниже).

- **По умолчанию: шаблон (ключ не нужен).** Ответы чистятся от слов-паразитов: «ну», «вот», «короче», «типа», «как бы», «значит», «в общем», «собственно», «наверное», протяжные «ааа», «эээ», «ммм», а также «что-нибудь такое». Если после чистки остались только пустые слова вроде «это», «так», «ладно», «ок», ответ считается пустым. У списков убираются вводные «нужны», «требуется», «должен знать». Список режется по запятым, «и», «а также», точкам с запятой и переносам строки. Факты не выдумываются и не пересказываются: что сказал человек, то и в тексте. Заглавная ставится у русской строчной буквы, латинские имена вроде amoCRM не меняются.
- **С нейросетью Claude (необязательно, для разработчиков).** Нужен «ключ API»: личный пароль доступа к Claude от компании Anthropic; обычный пользователь его не вводит. Разработчик вставляет ключ на скрытой странице `index.html#settings`, он запоминается только в этом браузере. Тогда текст вакансии пишет нейросеть, а не шаблон: запрос идёт из браузера прямо в `api.anthropic.com` (модель по умолчанию `claude-haiku-5-5`, до 1500 токенов, таймаут 60 секунд). Нейросеть возвращает ответы по темам и текст 100–180 слов, ничего не выдумывает, пропуски называет в `missing`. Без ключа ответы пользователя никуда не уходят.
- Любой сбой нейросети (таймаут, нет сети, 401, 403, 404, 429, неверный JSON, прочий сбой) показывает экран ошибки. «Собрать по шаблону» доступно при наличии ключа.
- Время сборки без ключа: около одной-двух секунд, экран «Создаём вакансию…» без кнопок. При сборке через Claude (до минуты) на экране есть ссылка «Отмена»: она останавливает сборку и возвращает к ответам.
- Для демонстрации сбоя: адрес с `?fail`, первая попытка падает, повтор проходит.

## 10. Документ вакансии

Экран результата это сам документ: текст вакансии главный и помещается на один экран без прокрутки (окно от 720 px шириной и высотой от примерно 770 px). Верхней карточки нет. В шапке документа слева «Вакансия», справа метка статуса: «Готова» (зелёная точка) или «Черновик» (жёлтая). Короткие разделы помечены рядом с названием словом «коротко», пустые показывают кнопку «Добавить», отдельной строки «Не хватает…» нет. Кнопки под текстом документа: «Скопировать» (главная) и «Новая вакансия». Одинаковые у готовой вакансии и у черновика; если не осталось ни одного раздела, только «Новая вакансия». Если текст уже скопирован, «Новая вакансия» сразу открывает первый вопрос. Если нет, первое нажатие просит подтвердить («Стереть и начать заново?» на 3 секунды), второе стирает всё.

```
Вакансия

Ищем специалиста.

Чем предстоит заниматься
• пункт     (из ответа 1)
Проект, над которым идёт работа
Фраза.      (из ответа 2)
Ближайшие полгода
Фраза.      (из ответа 3)
Инструменты и знания
• пункт     (из ответа 4)
```

- «Ищем специалиста.» — это связка, а не должность. Появляется, если есть хотя бы один ответ.
- Раздел без ответа показывает кнопку «Добавить» вместо текста.
- Правка: клик по разделу или карандаш (виден при наведении, на сенсорных экранах всегда). Поле правки и две кнопки-иконки: «Сохранить» (имя кнопки и подсказка, Ctrl/Cmd+Enter) и «Отмена» (Esc). На экране это галочка и крестик, не текстовые кнопки. Списки правятся по одному пункту на строку.
- Копирование: кнопка «Скопировать» кладёт в буфер тот же документ простым текстом, пункты через «— ». Кнопка меняется на «Скопировано» на 2 секунды. Если нет ни одного ответа, кнопки нет.
- «Начать заново» стирает ответы и сразу открывает первый вопрос.
- Документа под кругом нет, пока идёт интервью. Пометки «проверьте текст» под документом нет.

## 12. Нефункциональные требования

- **Браузеры:** Chrome и Edge текущей версии (голос и текст), Firefox (только текст, проверено), Safari (текст проверен, голос не проверялся).
- **Экраны:** от 320 px. До 600 px кнопки в одном ряду, круг 208 px, поля документа 20 px. Горизонтальной прокрутки нет.
- **Темы:** светлая и тёмная, по умолчанию тёмная, переключатель в шапке, цвета только через переменные (см. `HANDOFF.md`). Выбранная тема запоминается в этом браузере.
- **Доступность:** уровень WCAG 2.2 AA для текста (4,5:1), видимый фокус, подписи у кнопок-иконок, статусы в `aria-live`, ошибка не только цветом, `prefers-reduced-motion`.
- **Данные:** принятые ответы и недописанный текст в поле живут в памяти страницы и в `sessionStorage` вкладки, пока интервью не закончено. После закрытия вкладки пропадают. Готовый документ не сохраняется. В `localStorage` лежат только ключ и модель Claude, если их ввели, и выбранная тема.
- **Зависимости:** нет сборки, нет библиотек. Шрифт Inter с Google Fonts, остальное в одном файле.

## 14. Что решили и что убрали

| Решение | Почему |
|---|---|
| Интервью по одному вопросу вместо свободного рассказа | Проще поток, нечего разбирать по темам, человек всегда знает, что отвечает |
| Одно поле для голоса и текста | Два режима не нужны: диктовка и набор живут в одном месте |
| Номер вопроса убран, прогресс только кругом | Подпись дублировала круг и «прыгала» рядом с таймером |
| Пометки «проверьте текст» под документом нет | Решение автора: не шуметь, текст остаётся правкой по клику |
| Подсказки «Чтобы отредактировать, нажмите на раздел» нет | Правка находится сама: карандаш при наведении, курсор-текст |
| Название «Hire» вместо «Искра» | Продукт выдуманный, чужое название не берём |
| Формулировки вопросов с «сотрудник» вместо «он» | В интервью «он» без пояснения непонятно. Отличие от задания осознанное |
| «Отмена» на сборке только при работе через Claude | Долгую операцию нужно уметь отменить: шаблонная сборка занимает секунды и без кнопок, Claude до минуты |
| Ответы и недописанный текст переживают обновление страницы | Контекст не должен теряться при обновлении страницы. Хранится только в `sessionStorage` этой вкладки, стирается по «Начать заново» и после сборки. Готовый документ не хранится |
| Поиск, язык и уведомления в шапке выключены | Раньше нажимались и ничего не делали; теперь выглядят выключенными, как пункты меню |
| Боковое меню на шаге интервью не сворачиваем | Проверили по разбору и исследованию: данных за скрытие мало, они расходятся, выход из процесса должен быть виден; автор оставила меню как в настоящем сервисе |
| «Пропустить» остаётся той же ширины, что «Дальше», с рамкой без заливки | Источники советуют делать такое действие тише главного, но не уменьшать; равная ширина выравнивает пару, решение автора |
| Подпись «остаётся на этом проекте / берёт другой» не делаем | Различить эти случаи шаблоном ненадёжно |
| Микрофон по центру круга убрали | Иконка не нужна, голос показывает сам круг |
| Крестик с подтверждением вместо окна | Окно мешает потоку, подсветка крестика достаточна |
